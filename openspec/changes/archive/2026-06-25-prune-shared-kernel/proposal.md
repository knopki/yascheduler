## Why

`yascheduler.shared` was populated by a retrofit, not by a principle. The `2026-06-23-shared-kernel-extraction` change moved `variables.py` and `async_utils.py` into `shared/` at the same commit that introduced the spec whitelisting "process-global constants" and "pure runtime helpers" as permitted categories — the spec codified what was already done rather than what the layer should contain. A `# FIXME: is this really shared kernel? decide` marker in `variables.py` was written in that same commit and never resolved. Two subsequent changes (`add-entrypoints-layer`, `consolidate-daemon-entrypoints`) migrated every CLI consumer of `to_sync` to `asyncio.run`, leaving `async_utils.to_sync` with a single consumer (`entrypoints/client.py`) and `variables.{CONFIG_FILE,LOG_FILE,PID_FILE}` with consumers only in the `entrypoints` layer. The shared kernel now holds leaf utilities consumed by one layer each, kept there by a negative definition ("not business logic, not SSH/DB/HTTP I/O") that cannot distinguish a true cross-layer kernel from a misplaced module. This change prunes `shared/` to its honest content (`compat.py`, the only module consumed by ≥2 architectural layers) and relocates the rest to the layers that actually consume them.

## What Changes

- **Relocate** `yascheduler/shared/variables.py` → `yascheduler/entrypoints/paths.py` (path constants for config/log/pid files; all consumers are in the `entrypoints` layer). Update `# FILE:` header, `MODULE_CONTRACT`, `MODULE_MAP`, `CHANGE_SUMMARY`.
- **Inline** `to_sync` (plus its `ParamT`/`ReturnT_co` TypeVars) into `yascheduler/entrypoints/client.py` as a private helper. Single consumer; the six CLI consumers were removed by `consolidate-daemon-entrypoints`.
- **Inline** `asleep_until` into `yascheduler/application/orchestrator.py` as a private helper. Single consumer (two call sites in that one file).
- **Delete** `yascheduler/shared/async_utils.py` (empty after the two inlines).
- **Remove** `ParamSpec` from `yascheduler/shared/compat.py`. It is used only by `to_sync`'s signature; after the inline, no production code imports `ParamSpec` from `shared`. `compat.py` keeps `Self` and `Unpack`.
- **Rewrite** `yascheduler/shared/__init__.py` facade: drop re-exports of `to_sync`, `asleep_until`, `CONFIG_FILE`, `LOG_FILE`, `PID_FILE`, `ParamSpec`; keep `Self`, `Unpack`. Rewrite the `MODULE_CONTRACT` `SCOPE` from the negative "no business logic, no I/O, no domain types" to a positive definition: `shared` contains only typing shims consumed by ≥2 architectural layers.
- **Update** `yascheduler/__init__.py` to re-export the path constants from `yascheduler.entrypoints` (via the layer facade) instead of `yascheduler.shared`. `M-MAIN` drops its dependency on `M-SHARED`.
- **Extend** `yascheduler/entrypoints/__init__.py` facade to re-export `CONFIG_FILE`, `LOG_FILE`, `PID_FILE` from `.paths` (R2: `entrypoints/cli/*` consume them cross-subpackage via the layer facade).
- **Rewrite consumer imports**: `entrypoints/cli/{args,init,daemon_sysv}.py` switch to `from yascheduler.entrypoints import CONFIG_FILE, LOG_FILE, PID_FILE`; `entrypoints/client.py` imports the path constants from the sibling `.paths` (R1 within `entrypoints`).
- **Rewrite test imports**: 7 test files switch `from yascheduler.shared import CONFIG_FILE` (and `LOG_FILE`/`PID_FILE`) to `from yascheduler import CONFIG_FILE` (the public-API re-export path, stable per `package-facades` "Public API stability" requirement).
- **Update OpenSpec spec** (`package-facades`, decision-level — full unfreeze chain on the affected requirements):
  - Rewrite the shared-kernel definition from negative ("no business logic, domain types, or I/O") to positive ("typing shims consumed by ≥2 architectural layers; a module whose consumers are in a single layer belongs to that layer, not to `shared`"). Keep the "no SSH/DB/HTTP/cloud I/O" clause as a second guardrail.
  - Update the "Public API stability" requirement: path constants are re-exported through `yascheduler.entrypoints.paths` (not `yascheduler.shared.variables`); `from yascheduler import CONFIG_FILE, LOG_FILE, PID_FILE` remains resolvable.
  - Remove the scenario pinning `to_sync` to `yascheduler.shared.async_utils` (the symbol is now a private helper in `entrypoints/client.py`).
  - Update the `compat.py` scenario: `Self` and `Unpack` are importable via `from yascheduler.shared import Self, Unpack`; `ParamSpec` is no longer re-exported (consumed only inside `to_sync`'s former definition).
  - Remove the standing `# FIXME: is this really shared kernel? decide` marker from `variables.py` (the file moves; the question is resolved by this change).
- **Update GRACE artifacts**: `docs/knowledge-graph.xml` — `M-SHARED` loses annotations for `to_sync`/`asleep_until`/`CONFIG_FILE`/`LOG_FILE`/`PID_FILE`/`ParamSpec`, retains `Self`/`Unpack`; new `M-ENTRYPOINTS-PATHS` module entry; `M-ENTRYPOINTS` gains path-constant re-export annotations; `M-MAIN` `<depends>` drops `M-SHARED` and the `M-MAIN → M-SHARED` `CrossLink` is removed; `M-APPLICATION-ORCHESTRATOR` may gain a private `asleep_until` annotation (optional per GRACE-lite "private helpers" guidance).
- **Run parallel to `relocate-di-to-entrypoints`**: both changes edit `package-facades/spec.md` and `entrypoints/__init__.py`, but on disjoint spec lines and disjoint facade symbols (this change touches path-constant scenarios; `relocate-di` touches `di`/`make_daemon`/`CLIDeps` scenarios). Deltas merge at archive time.

## Impact

- **Code**: 1 file moved (`variables.py` → `entrypoints/paths.py`); 1 file deleted (`shared/async_utils.py`); 2 functions inlined into their sole consumers (`to_sync` → `entrypoints/client.py`, `asleep_until` → `application/orchestrator.py`); `shared/compat.py` loses `ParamSpec`; `shared/__init__.py` facade shrinks to `Self`+`Unpack`; `entrypoints/__init__.py` facade gains 3 path constants; `yascheduler/__init__.py` re-export source switches; ~9 production consumer imports rewritten; 7 test files rewritten.
- **APIs**: The public re-export path `from yascheduler import CONFIG_FILE, LOG_FILE, PID_FILE` is unchanged (still resolvable, now via `yascheduler.entrypoints.paths` instead of `yascheduler.shared.variables`). The deep path `from yascheduler.shared import to_sync` **BREAKS** — `to_sync` is now a private helper in `entrypoints/client.py`. No external consumer is known: the six CLI consumers were removed by `consolidate-daemon-entrypoints` and `to_sync` was never part of the `pyproject.toml` `[project.scripts]` surface. The deep path `from yascheduler.shared import ParamSpec` **BREAKS** — `ParamSpec` is removed from `compat.py`; only `to_sync`'s former signature used it. No external consumer is known. The deep path `from yascheduler.shared import asleep_until` **BREAKS** — inlined to `application/orchestrator.py`. No external consumer is known.
- **Dependencies**: none added or removed.
- **Config**: `pyproject.toml` unchanged. The `layers` contract still lists `yascheduler.shared` as the bottom layer (now containing only `compat.py`); the `forbidden` contract `shared → config` stays in force (`config` still imports `Self` from `shared`, so the cycle risk remains real).
- **GRACE**: `M-SHARED` annotation list shrinks; `M-ENTRYPOINTS-PATHS` added; `M-MAIN` `<depends>` updated; one `CrossLink` removed.
- **Active changes**: `relocate-di-to-entrypoints` (no-tasks) edits `package-facades/spec.md` on disjoint lines (di/make_daemon/CLIDeps scenarios) and disjoint `entrypoints/__init__.py` symbols; `schema-migrations` (in-progress) does not touch `shared/` or `entrypoints/paths.py`. No conflict.
- **Compatibility**: **BREAKING** for any external importer of `from yascheduler.shared import {to_sync, ParamSpec, asleep_until}`. All three were internal utilities; no `[project.scripts]` entry references them, and the post-`consolidate-daemon-entrypoints` codebase has no production consumer of `to_sync` outside `client.py` or of `asleep_until` outside `orchestrator.py`. Acceptable per the project's stability policy (internal API is not part of the public contract keyed on `from yascheduler import <name>`).
