## 4. Enrich `manager.py` contracts

Edit only contract comment fields; do NOT touch code, signatures, or the existing inline failure-path comment block. Existing `METHOD_*` regions already wrap the entire method — keep that invariant.

- [x] 4.1 `MODULE_CONTRACT`: add `INVARIANTS` (`CloudProvisionerImpl` owns no persistence: no `NodeRepository`, no `PostgresUnitOfWork`, no DB import; the success-path SSH session stays registered under `node.node_id` for orchestrator reuse; the setup-failure `machine_repository.disconnect(node.node_id)` is a safe no-op when no session was ever registered for that id)
- [x] 4.2 `CLASS_CloudProvisionerImpl`: add `INVARIANTS` (satisfies the `CloudProvisioner` Protocol structurally; `allocate`/`deallocate` are async; `select_provider`/`stop` semantics per spec)
- [x] 4.3 `METHOD_allocate`: add `ENSURES` (returned `Node.node_id == node.node_id`; `hostname`, `external_id`, `username`, `port`, `jump_host`, `jump_port`, `jump_username` copied from the `CloudCreateNodeDTO`; `cloud == adapter.name`; on success `enabled=True` and `ncpus is None` — the standalone `get_cpu_cores()` is NOT invoked here). Add `INVARIANTS` (`machine_repository.connect(...)` is called WITHOUT `jump_host` / `jump_username` kwargs; the final `replace(node, enabled=True, ...)` carries no `ncpus=` kwarg). Add `RATIONALE` Q/A — why `await disconnect(node.node_id)` on the setup-failure path BEFORE `delete_node`? - [x] 4.4 `METHOD_deallocate`: add `INVARIANTS` (identifies the VM via `node.external_id`, NOT `node.hostname`; `node.cloud is None`, missing adapter, and missing config each produce a warning + early return)

- [x] 4.6 `METHOD_stop`: add `RATIONALE` Q/A — why is it safe to call `disconnect_all` from both `clouds.stop()` and `Orchestrator.stop()` on the shared instance? (`disconnect_all` is idempotent — the second call is a no-op)
- [x] 4.7 `METHOD__setup_vm`: add `INVARIANTS` (does NOT modify `jump_host`, `jump_port`, or `jump_username` on the Node — the DTO mapping in `allocate` is the sole source for these fields)
- [x] 4.8 `METHOD__connect_to_vm`: add `INVARIANTS` (`machine_repository.connect(...)` is called WITHOUT `jump_host` / `jump_username` keyword arguments — only `node`, `client_keys`, `connect_timeout`, `data_dir`, `engines_dir`, `tasks_dir`)
